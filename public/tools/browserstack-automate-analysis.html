BrowserStack Automate API, assessed for embedding into Snurra

BrowserStack Automate is cloud test-execution infrastructure — it runs your Selenium/Playwright/Cypress scripts on 3,500+ real browser/OS combinations and thousands of real mobile devices, then exposes each session's status, console logs, network logs, screenshots and video over a REST API. This page maps its capabilities, how it would slot into Snurra's audit worker, what it costs, and — held to a strict 100%‑certain bar — exactly which feasibility‑catalog checks it can cover.

Prepared: 26 Jul 2026 Use case: Cross‑browser / real‑device / geo signal for the Snurra Site Audit Catalog: feasibility‑app · 217 checks
Bottom line up front
BrowserStack is not a scanner — it never judges a page on its own. It is an execution grid: you script the assertion, it supplies a real browser, real device, or a specific country's IP and captures the artifacts. So its value is narrow but genuine: it covers checks that need a real environment — real Safari/iOS behaviour, real‑device mobile UX, cross‑browser JS/console differences, and IP‑geolocation from a specific country. Everything it covers must reduce to a deterministic scripted assertion; it does zero security, SEO, a11y‑engine, content, visual‑diff or performance‑vitals scanning.

The defining constraint

BrowserStack does no autonomous scanning. It will not tell you a page has a broken CTA, a JS error or a mixed‑content resource unless your script asserts it. Every check it "covers" is a deterministic assertion you write and run on its grid — its contribution is the real environment and the captured artifacts, not a verdict.

Auth & format

HTTP Basic auth (username : access_key), JSON responses, standard HTTP status codes. Base host api.browserstack.com.

Plan · Projects · Builds · Sessions

List/get/update/delete across the hierarchy: a project holds builds, a build holds sessions. Query plan usage & parallel limits programmatically.

Session status

Each session returns status (passed/failed) plus your marked result — the pass/fail your assertion produced.

Console logs

Per‑session browser console log (default = errors; Chrome exposes a raw endpoint) — the source for JS‑error & chunk‑load‑failure checks.

Network logs (HAR)

Full HAR of requests/responses/status/timing — the source for mixed‑content, script‑404, request‑timing & tag‑firing checks.

Screenshots & video

Automatic step screenshots and a session video, retrievable by URL — evidence for the audit UI.

Async by nature

Unlike a single request/response scanner API, a BrowserStack check is a two‑phase job: your worker starts a session (the script runs on the grid), then polls the session/logs endpoints until it finishes and pulls the artifacts. This shapes the Snurra adapter (see Embedding).

06 · Which catalog checks it can cover

Coverage — held to a 100%‑certain bar

A check is listed only if its pass/fail is a deterministic scripted assertion (DOM geometry/state, console error, network status/timing, navigation/redirect outcome, cookie/storage, or a completed interaction) that a BrowserStack session can produce with no human, AI‑text or visual‑diff judgment. This is the full set of checks a BrowserStack session can cover on its own.

Additional checks it can cover — not in the catalog

Deterministic verdicts BrowserStack’s real-device / real-browser grid can produce (via your assertion) that have no matching entry in checks.ts — candidate additions to the catalog. Each is referenced.

What the Automate API does NOT cover

Excluded entirely, because the Automate API cannot deliver these verdicts on its own: Accessibility / WCAG (BrowserStack's separate Accessibility product, not Automate) · SSL/TLS & security headers · SEO facts (title, meta, canonical, sitemap, robots, hreflang) · all AI‑text / compliance checks (REMS, ISI, PI links, GDPR wording, geo content) · performance vitals (LCP/INP/CLS/CrUX/page‑weight) · visual‑diff & brand consistency · content quality / readability / duplication · uptime / DNS / domain‑expiry · regulatory intelligence · competitive benchmark · audit‑trail & deep‑dive / stakeholder workstreams.
