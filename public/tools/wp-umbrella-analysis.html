WP Umbrella, assessed for embedding into Snurra

Fits into Snurra: API + setup Public REST API (Bearer token) but it reads only your own onboarded WordPress sites — each needs the WP Umbrella plugin installed + connected; not an arbitrary-URL scanner.

WP Umbrella is a WordPress maintenance & monitoring platform for agencies running fleets of WordPress sites. You install its free plugin on each site and it monitors uptime, SSL & domain status, response time, PHP errors, tracks core/plugin/theme updates and known vulnerabilities (Patchstack), runs backups, scans for broken links & images, and produces white‑label maintenance reports. It exposes a Bearer‑token public REST API that reads back your projects' maintenance data — but only for the WordPress sites you own and have onboarded. This page maps its capabilities, how it could slot into Snurra's worker, what it costs, and — held to a strict 100%‑certain bar — precisely which feasibility‑catalog checks it can cover.

Prepared: 29 Jul 2026 Use case: WordPress-fleet uptime / SSL / maintenance monitoring for the Snurra Site Audit Catalog: feasibility‑app · 217 checks
Bottom line up front
WP Umbrella is a WordPress-fleet maintenance monitor, not a URL-in site scanner. Against this catalog it maps cleanly onto just 6 checks — the uptime / SSL-expiry / domain-expiry / broken-link family it monitors continuously — but its real value is a large net-new WordPress-maintenance surface the catalog doesn't yet cover: grouped PHP error monitoring, outdated core/plugin/theme detection, known-vulnerability alerts (Patchstack), server response-time trends, backup integrity, malware scanning and pre/post-update visual regression. It has a Bearer-token public REST API (public-api.wp-umbrella.com) — but it reads back only the WordPress sites you own and have onboarded (its plugin installed + API key connected). The catch for Snurra: it's an owned-fleet, agent-on-site model, not "POST a URL, get an audit". It does not do Core Web Vitals / Lighthouse scoring, SEO, or arbitrary-URL scanning.

01 · What WP Umbrella actually does

Capabilities

Two layers matter for embedding: what the plugin monitors on each connected WordPress site (uptime, SSL, errors, updates, backups, links) and its automation surface (the Bearer-token public REST API, webhooks and native integrations a backend drives it through). Toggle between them:

Uptime, SSL & domain monitoring

Continuously checks each site's uptime, SSL and domain status, at a configurable 2–30 min interval, and alerts via email/Slack on downtime or SSL/domain expiry. Uptime history is tracked over time.

UptimeSSL / domain expiry

Performance (response time)

Tracks server response time and HTTP errors over time (desktop & mobile), filterable by date. It is a response-time trend monitor — not a Lighthouse / PageSpeed / Core-Web-Vitals score.

Response timeTrend

PHP error monitoring

Automatically captures PHP errors across the fleet, grouped with stack traces — error type, file, line and message — so you see recurring fatals/warnings without enabling WP debug on the live site.

PHP errorsStack traces

Updates (Safe Update)

Tracks and applies WordPress core, plugin & theme updates — bulk or scheduled — with pre-update backups, update validation and rollback visibility; auto cache-clear & DB upgrades for WooCommerce/Elementor.

Core/plugin/themeRollback

Vulnerability & malware

Monitors known vulnerabilities in installed components (Patchstack data) on every plan; an optional Site Protect add-on adds a firewall + virtual patching, daily malware scanning, IP blocklist and an activity log.

Patchstack CVEsMalware (add-on)

Backups

Encrypted, GDPR-compliant, scheduled backups (down to hourly with the add-on) with one-click restore of files and database. Backup completion is tracked per site.

EncryptedOne-click restore

Broken links & images

Scheduled scans for broken links and broken images across each site, surfaced in a centralized issue list per project — the closest thing to a site-crawl verdict WP Umbrella produces.

Broken linksBroken images

Visual regression (on updates)

Takes before/after visual snapshots around updates so a plugin/theme/core update that breaks a page's rendering is caught. Update-scoped — not a general per-run visual baseline.

Pre/post-updateVisual diff

Maintenance reports

Automated white-label PDF reports documenting updates applied, backups taken, uptime and monitoring over a period — the agency-facing deliverable, scheduled per client.

White-label PDFScheduled

The defining shape (for embedding)

WP Umbrella's verdicts are deterministic maintenance signals for a WordPress site you control: it is up or down, the SSL/domain expires on date X, this PHP error fired N times, these components are outdated/vulnerable, this link 404s. That's genuinely useful — but every signal comes from a plugin installed on the site plus its WordPress REST API, so it only works on owned, onboarded sites, never an arbitrary client URL. Note its "performance" is server response time, not a Core-Web-Vitals / Lighthouse score.

Public REST API

Base https://public-api.wp-umbrella.com. Read your maintenance data programmatically — resources seen in the official Postman collection: Me, Projects (sites), Vulnerabilities. It reads out your fleet's data; it is not a scan-trigger API.

JSONread-out

Auth — Bearer token

Generate an accessToken on your Profile page ("Generate my token") and send it as a Bearer header. Requests are scoped by projectId for a given site.

Plugin + WP REST API

Each site is onboarded by installing the free WP Umbrella plugin and pasting an API key; the platform talks to the site over its WordPress REST API. Sites that block the WP REST API (Wordfence/Sucuri, HTTP-Basic-Auth) can fail to connect.

PluginOwned sites

Webhooks & scheduling

Webhooks are offered for advanced workflows/notifications, alongside scheduling for backups, updates, link checks and reports. Monitoring runs on the platform's own 2–30 min cadence.

How Snurra could drive it — and the catch

There is a real HTTP adapter here: isConfigured() gates on the Bearer accessToken, buildRequest() reads Projects / Vulnerabilities for a projectId, mapResponse() maps the maintenance data. But it is not URL-in: the site must already be a WP Umbrella project with the plugin installed, so this only works for a WordPress fleet Snurra (or its client) owns and onboards — degrade to not-applicable for any site not in the account. The exact API JSON shapes are unverified (developer docs unreachable) — confirm against the live Postman collection before building.

02 · Applicability — how it slots into Snurra

06 · Which catalog checks it can cover

Coverage — held to a 100%‑certain bar

A check is listed only if WP Umbrella can produce its verdict deterministically for an onboarded WordPress site — an up/down state, an SSL/domain expiry date, a broken-link result — no human, AI-text or visual judgment. Because WP Umbrella is a WordPress-fleet maintenance tool rather than a URL-in site scanner, catalog overlap is deliberately small; its real value is the net-new maintenance surface listed below. Every listed check also assumes the site is onboarded (plugin installed) — it can't run against an arbitrary URL.

Additional checks it can cover — not in the catalog

Deterministic checks WP Umbrella covers that have no matching entry in checks.ts — candidate additions to the catalog. Each is referenced.

What WP Umbrella does NOT cover (for Snurra)

Excluded, because WP Umbrella can't deliver these verdicts (or only for owned WordPress sites): arbitrary-URL scanning (everything requires the plugin on a site you control) · non-WordPress sites (out of scope entirely) · Core Web Vitals / Lighthouse / PageSpeed scoring (its "performance" is server response time, not a CWV score) · SEO (titles, meta, structured data, canonicals — no SEO product) · analytics / tag integrity & consent (GA/GTM firing, pre-consent tracking, CMP validation) · accessibility / WCAG · content-meaning & compliance wording · and geo content correctness. Its 1-check-per-minute uptime floor is 2 min, so it can't satisfy checks that specify a 1-min interval.
