ImmuniWeb, assessed for embedding into Snurra

ImmuniWeb is an AI‑driven application‑security & compliance testing platform. For a website Site‑Audit the natural embed surface is its free Community Edition REST APIs — the Website Security Test (HTTP security/privacy headers, cookies, HTTP methods, software/CVE, PCI‑DSS & GDPR quick‑scans, DNSSEC, SRI), the SSL Security Test (TLS grade, cert validity, weak ciphers, post‑quantum readiness) and the Dark Web Exposure Test (leaked credentials). Each takes a URL/domain in and returns a grade + per‑check findings via a documented async job/poll API (plus the iwtools CI CLI). This page maps its capabilities, how it slots into Snurra's worker, what it costs, and — held to a strict 100%‑certain bar — precisely which feasibility‑catalog checks it can cover, plus the security checks it covers that the catalog does not yet have.

Bottom line up front
ImmuniWeb's free Website Security Test + SSL Security Test take a URL in and return deterministic per‑check verdicts. Against this pharma‑oriented catalog it maps cleanly onto 6 catalog checks (the SSL/TLS + security‑header + mixed‑content family), but its real value is a large net‑new security & compliance surface the catalog doesn't yet cover — per‑directive CSP analysis, cookie Secure/HttpOnly/SameSite flags, insecure HTTP methods, known‑CVE component detection, PCI‑DSS 4.0 & GDPR technical quick‑scans, DNSSEC, SRI validation and dark‑web credential leaks. It embeds behind an HTTP adapter as an async start‑then‑poll provider (POST to start → poll get_result). The catch: the free API is capped at 50 requests / 24h / IP and CVE/software‑version detail is gated behind a paid API key (commercial API from $200/mo).

01 · What ImmuniWeb actually does

Capabilities

Two layers matter for embedding: what the free scanners check (the headers, cookies, TLS, software, compliance signals and dark‑web exposure they verdict from a URL) and its automation surface (the async REST API, the iwtools CLI and the paid products a backend drives it through). Toggle between them:

HTTP security & privacy headers

Presence, syntax and validity of every security header — CSP (per‑directive analysis: unsafe‑inline, wildcard, empty), HSTS (max‑age/includeSubDomains/preload), X‑Frame‑Options, X‑Content‑Type‑Options, Referrer‑Policy, CORS, COOP/COEP/CORP, Permissions‑Policy.

Per‑cookie Secure, HttpOnly, SameSite, Domain/Path/Max‑Age/Expires, and __Secure‑/__Host‑ prefix validation. Verdicts like "the cookie has neither Secure nor HttpOnly flags set".

Detects allowed verbs (GET/POST/HEAD/OPTIONS/TRACE/TRACK/PUT/PATCH/DELETE/CONNECT) and flags potentially insecure methods enabled on the server.

The defining strength (for embedding)

ImmuniWeb's Website Security Test verdicts are deterministic captures from a URL: a header is present/valid or not, a cookie carries Secure/HttpOnly or not, a TLS grade, a detected component maps to a CVE — no human, AI‑text or visual judgment. That security/compliance surface is where it's strongest and where it adds checks this catalog does not have. Two caveats for embedding: the free API is capped at 50 requests/24h/IP, and software‑version + CVE detail is cut unless you supply a paid API key.

How Snurra would actually drive it

A ProviderAdapter like the PSI one, but async two‑phase: buildRequest() POSTs tested_url to /websec/api/v1/chsec/[ts].html; the adapter then polls /websec/api/v1/get_result/[ts].html with the returned job_id until in_progress clears; mapResponse() reads the per‑check objects (http_headers, http_cookies, app_scan, gdpr, pci_dss_4…) into neutral check inputs. Gate isConfigured() on the api_key for CVE‑level checks; degrade to not‑applicable when the key is absent or the free cap (50/24h/IP) is hit. Schedule scans off the hot path — the free cap makes inline per‑request calls a non‑starter.

02 · Applicability — how it slots into Snurra

Embedding paths, ranked

ImmuniWeb fits Snurra's existing pattern — an HTTP service behind a ProviderAdapter, like PageSpeed — with two twists: calls are async start‑then‑poll (POST to start → poll get_result), and the free‑tier cap (50 req/24h/IP) shapes every path. Integration shape (contrast with the sync tools)

Like PSI it's an HTTP adapter, but unlike PSI's single GET it is async: buildRequest() POSTs tested_url to start a test; the adapter polls get_result with the returned job_id until in_progress clears (iwtools polls every ~10s); mapResponse() reads the per‑check objects. No webhook is documented — it's poll‑based. Gate isConfigured() on the api_key for CVE‑level checks; back off on the 3‑min / 24h rate errors; and because the free cap is tight, keep scans scheduled + cached by URL, never on the per‑request path.

03 · Technical detail — API, rate limits & the free‑tier cap

What integrating actually looks like

Enough to scope an integration spike. Expand for detail:

HTTP/HTTPS POST. Start a test, then poll for its result. The [ustamp] path segment is an arbitrary integer used as a cache‑buster.
# 1) start a Website Security Test — URL in
curl -X POST https://www.immuniweb.com/websec/api/v1/chsec/1699999999.html \
  -d 'tested_url=https://example.com&recheck=false'
# → { "status":"test_started", "job_id":"…", "status_id":1 }
# or { "status":"test_cached", "test_id":"…", "status_id":3 }

# 2) poll until in_progress (status_id:2) clears
curl -X POST https://www.immuniweb.com/websec/api/v1/get_result/1699999999.html \
  -d 'job_id=…'
# → { "grade":"A", "score":90, "http_headers":{…}, "http_cookies":{…},
# "http_verbs":{…}, "pci_dss_4":{…}, "gdpr":{…}, "dnssec":{…},
# "app_scan":{…}, "third_party_content":{…} }

06 · Which catalog checks it can cover

Coverage — held to a 100%‑certain bar

A check is listed only if ImmuniWeb's free Website Security Test or SSL Security Test produces its verdict as a deterministic capture from a URL — a security header present/valid, a TLS grade / cert state, a mixed‑content finding. This catalog is pharma‑website‑audit oriented, so ImmuniWeb (a security scanner) maps onto a small but 100%‑certain SSL/TLS + security‑header slice; its real value is the net‑new security & compliance checks below. Anything ImmuniWeb only partly determines is left out.

Additional checks it can cover — not in the catalog

This is where ImmuniWeb earns its keep: deterministic security & compliance checks it covers that have no matching entry in checks.ts — strong candidates to add to the catalog. Each is referenced; free unless marked premium.

What ImmuniWeb does NOT cover (for Snurra)

Excluded, because ImmuniWeb can't deliver these verdicts from a URL scan: content / compliance meaning (REMS / ISI / PI, CCPA‑vs‑GDPR wording, privacy‑policy content — AI‑text judgments) · analytics & tag integrity (GA4 firing, duplicate pageviews, correct property, dataLayer) · geo content routing · visual regression · performance / Core Web Vitals · accessibility / WCAG · functional interaction (forms, CTAs, journeys) · uptime monitoring. It is a security/SSL/privacy‑compliance scanner, not a full site‑audit engine. Also: CVE‑level component detail requires a paid API key, and the free API is capped at 50 req/24h/IP.
